# 文档代码修正说明

来源：《尚硅谷大模型技术之智图寻宝》V2.0.0 的各模块正式代码清单。现有去噪模块也存在运行错误，先备份后修复。下列“段落号”是从 `word/document.xml` 提取的零基段落序号，不是 Word 页码，可按代码关键词在原文查找。

## 训练与检索逻辑修正

| 原问题 | 当前行为与原因 |
|---|---|
| 训练/验证没有明确设置 `.train()`、`.eval()` | 每轮显式切换模式；验证及推理禁用梯度。当前简单 CNN 没有 BN/Dropout，遗漏模式切换不一定改变现有结果，但接口应正确 |
| 简单平均各批损失，尾批与整批权重相同 | 按样本数加权；空加载器明确报错，避免除零 |
| `drop_last=True` 丢弃尾批，小数据集甚至没有批次 | 保留尾批；不足两张图时拒绝划分 |
| 去噪验证每次重新采样噪声，比较条件漂移 | 训练仍用随机噪声，验证按固定种子和图片索引生成噪声 |
| 文档建库过程一次把全部图片加载进字典 | DataLoader 分批读图、计算、入库，避免额外保存全量图片数组 |
| 自定义 Chroma 嵌入函数把传入编码器强制搬到 CPU，可能影响其他调用；还依赖图片输入协议 | 显式调用编码器生成 `embeddings`，查询用 `query_embeddings`，设备统一受 CLI 控制；不注册自动文本嵌入函数 |
| 原文注释称 Chroma 固定最多插入 5000 条 | 同时遵守配置批量和当前客户端 `get_max_batch_size()` 的实际限制 |
| 未明确指定距离度量，却在讲解中声称使用余弦 | 对向量做 L2 归一化，明确配置 cosine；全零和无效向量拒绝写库/查询 |
| 查询 `get_or_create_collection` 会静默创建空库 | 查询只读取已存在、已建完的集合；没有索引时明确提示建库 |
| 更换编码器后可能继续查询旧模型生成的向量 | 集合记录权重指纹，建库与查询必须一致；重建需要显式 `--rebuild` |
| 建库中断或旧图片删除后可能混入残留记录 | 记录 building/ready 状态；重新建库替换集合，不把半成品集合用于检索 |
| 训练结束直接使用最后一轮权重导出向量 | 重新加载验证损失最小的编码器，再导出向量及对应文件名 |
| 结果数量写死 5，库内不足 5 张时可能异常 | 查询数量取 `min(请求数量, 集合数量)` |
| CPU 下无条件调用 CUDA 随机种子操作 | 仅在 CUDA 可用时设置 GPU 随机种子，默认设备明确为 CPU |
| 权重路径、保存路径、加载路径在不同脚本中不一致 | 统一写入 artifacts，读写均使用相同路径约定和 `map_location` |

Chroma 的显式向量写入和查询方式参照官方 [Adding Data](https://docs.trychroma.com/docs/collections/add-data) 与 [Query and Get](https://docs.trychroma.com/docs/querying-collections/query-and-get)。实际接口还对照了当前环境中 Chroma 1.5.9 的函数签名并做了运行测试。

## 与错误修复分开记录的设计调整

以下属于接口清理或实现选择，不应全部称为语法错误。

1. 分类器输出改为原始 logits，训练使用 `CrossEntropyLoss`，推理时显式 softmax。原文 `log_softmax + CrossEntropyLoss` 并非必然报错，数学上也不能直接说成“无法训练”；这里去掉了重复的对数归一化，明确训练接口。
2. 相似模型解码器末层 ReLU 改为 sigmoid，使输出与 `[0,1]` 图像目标范围一致。这会改变数值行为，是设计调整；不是声称原 ReLU 在语法上错误。六层卷积/转置卷积结构和参数层名保留。
3. 文档编码器注释称五层、256×2×2，正式代码实际上有六层并最终输出 `[B,512]`。以正式代码为准，更正说明，不改成另一套五层网络。
4. 去噪模型的卷积通道数和参数层名保留，原 `F.sigmoid` 换为张量 `.sigmoid()`。原函数在可用版本中并不一定报错。
5. 原文未提供可直接使用的 `logo.jpg`、背景和按钮图标资源。页面保留文档布局、按钮和三栏对比，用文字标题替代缺失图片，移除无效背景链接，避免交付一组必然 404 的引用。
6. 前端支持直接对原图分类或检索；去噪后优先使用去噪图。换图和重新去噪会清空旧结果；上传或处理失败会显示提示。
7. 教材演示会先加噪再去噪，现改为显式勾选项；真实图片可直接去噪。命令行默认不额外加噪。
8. 训练产物增加 history、训练参数和文件名映射；已有权重输出目录拒绝覆盖。它们是工程补齐，不是教材语法错误。
9. 删除未使用的 shuffle buffer 等配置，公共代码放到 common，具体网络/数据/训练入口仍保留教材模块命名。
10. 原文结尾介绍提到对比损失、自适应噪声、椒盐噪声、感知损失、加权交叉熵等，正式代码清单未实现这些机制。本项目保持清单实际功能：两个 MSE 重建任务、一个交叉熵分类任务，不把介绍词当作已经实现的能力。

## 兼容性与尚未进行的工作

- 整理前现有 Python 源码保存于 `backups/source_before_assembly_*.zip`，包括用户已写的注释。
- 去噪模型结构与层名保留，同架构 state_dict 可加载。原根目录 `conv_autoencoder.pth` 结构来源未核实，没有自动迁移或覆盖。
- 分类和检索建议用当前版本重新训练；调整输出处理后，旧训练产物不等同于本次已验证模型。
- CPU 环境中已完成小样本流程验证，不代表正式准确率、检索质量或真实去噪效果达标。
- 尚未进行全量训练、CUDA 验证、服务器租用、部署或生产压测。
